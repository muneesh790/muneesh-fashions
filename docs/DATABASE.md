# Muneesh Fashions - Database Schema Design (V1)

This document outlines the exact Mongoose schema definitions for the Muneesh Fashions V1 application. It includes data types, validation rules, constraints, and relationships.

---

## 1. User Schema
Stores customer and admin account information.

*   `name`:
    *   **Type**: String
    *   **Required**: Yes
    *   **Validation**: Min length 2, Max length 50
*   `email`:
    *   **Type**: String
    *   **Required**: Yes
    *   **Unique Index**: Yes
    *   **Validation**: Must match standard email regex
*   `password`:
    *   **Type**: String
    *   **Required**: Yes (Hashed via bcrypt)
    *   **Validation**: Min length 6 (pre-hash)
*   `role`:
    *   **Type**: String
    *   **Enum**: `['customer', 'admin']`
    *   **Default**: `'customer'`
*   `addresses`:
    *   **Type**: Array of Objects (Optional)
    *   **Schema**:
        *   `firstName`: String (Required)
        *   `lastName`: String (Required)
        *   `phone`: String (Required)
        *   `addressLine1`: String (Required)
        *   `addressLine2`: String (Optional)
        *   `city`: String (Required)
        *   `state`: String (Required)
        *   `postalCode`: String (Required)
        *   `country`: String (Required, Default: 'India')
*   **Timestamps**: `createdAt`, `updatedAt` (Automatically managed by Mongoose)

---

## 2. Category Schema
Broad categorization for products (e.g., Men, Women, Accessories).

*   `name`:
    *   **Type**: String
    *   **Required**: Yes
*   `slug`:
    *   **Type**: String
    *   **Required**: Yes
    *   **Unique Index**: Yes
    *   **Validation**: Lowercase, URL-safe (e.g., "mens-wear")
*   `description`:
    *   **Type**: String
    *   **Required**: No
*   **Timestamps**: `createdAt`, `updatedAt`

---

## 3. Collection Schema
Thematic or seasonal collections for marketing (e.g., Summer 2024, Diwali Special).

*   `name`:
    *   **Type**: String
    *   **Required**: Yes
*   `slug`:
    *   **Type**: String
    *   **Required**: Yes
    *   **Unique Index**: Yes
    *   **Validation**: Lowercase, URL-safe
*   `description`:
    *   **Type**: String
    *   **Required**: No
*   `image`:
    *   **Type**: Object (Optional)
    *   **Schema**:
        *   `url`: String (ImageKit URL)
        *   `fileId`: String (ImageKit File ID for deletion)
*   **Timestamps**: `createdAt`, `updatedAt`

---

## 4. Product Schema
Stores the main product details, including multiple images, references to categories/collections, and embedded variants.

*   `name`:
    *   **Type**: String
    *   **Required**: Yes
*   `slug`:
    *   **Type**: String
    *   **Required**: Yes
    *   **Unique Index**: Yes
*   `description`:
    *   **Type**: String
    *   **Required**: Yes
*   `isActive`:
    *   **Type**: Boolean
    *   **Default**: `true`
    *   **Notes**: Used to hide products from the frontend without deleting them.
*   `category`:
    *   **Type**: ObjectId
    *   **Required**: Yes
    *   **Relationship**: References `Category` model
*   `collectionRef`:
    *   **Type**: ObjectId
    *   **Required**: No
    *   **Relationship**: References `Collection` model
*   `images`:
    *   **Type**: Array of Objects
    *   **Required**: Yes (Min 1 image)
    *   **Schema**:
        *   `url`: String (Required, ImageKit URL)
        *   `fileId`: String (Required, ImageKit File ID for deletion)
*   `variants`:
    *   **Type**: Array of Objects
    *   **Required**: Yes (Min 1 variant)
    *   **Schema**:
        *   `_id`: ObjectId (Auto-generated by Mongoose for each variant)
        *   `sku`: String (Required)
        *   `size`: String (Required, e.g., 'S', 'M', 'L')
        *   `color`: String (Required, e.g., 'Red', 'Blue')
        *   `pricePaise`: Number (Required, Allows varying price by size/color, Min: 0)
        *   `stock`: Number (Required, Min: 0, Default: 0)
*   **Timestamps**: `createdAt`, `updatedAt`

*Note on SKU Validation*: We cannot rely on a naive `unique: true` for the `sku` field inside an embedded array in Mongoose, as it can cause unexpected indexing issues or ignore uniqueness across documents. Instead, SKU uniqueness across the entire system must be strictly enforced via custom pre-save backend validation and explicit DB query checks before product creation or updates.

## 5. Cart Schema
A dedicated holding area for a user's intent to purchase. References the product and the specific variant.

*   `user`:
    *   **Type**: ObjectId
    *   **Required**: Yes
    *   **Unique Index**: Yes (A user can only have one active cart)
    *   **Relationship**: References `User` model
*   `items`:
    *   **Type**: Array of Objects
    *   **Required**: No (Can be empty)
    *   **Schema**:
        *   `product`: ObjectId (Required, References `Product` model)
        *   `variantId`: ObjectId (Required, Identifies the exact variant chosen)
        *   `variantSku`: String (Required, Saved alongside for easier debugging/display)
        *   `quantity`: Number (Required, Min: 1, Default: 1)
*   **Timestamps**: `createdAt`, `updatedAt`

---

## 6. Order Schema
Immutable record of a purchase. Copies product and variant details at the time of purchase.

*   `user`:
    *   **Type**: ObjectId
    *   **Required**: Yes
    *   **Relationship**: References `User` model
*   `items`:
    *   **Type**: Array of Objects (The Snapshot)
    *   **Required**: Yes (Min 1 item)
    *   **Schema**:
        *   `productId`: ObjectId (Required, References original `Product`)
        *   `variantId`: ObjectId (Required, References original Variant `_id`)
        *   `sku`: String (Required, Snapshot of variant SKU)
        *   `name`: String (Required, Snapshot of product name)
        *   `pricePaise`: Number (Required, Snapshot of variant price at time of purchase)
        *   `size`: String (Required, Snapshot of variant size)
        *   `color`: String (Required, Snapshot of variant color)
        *   `quantity`: Number (Required, Min: 1)
*   `subtotalPaise`:
    *   **Type**: Number
    *   **Required**: Yes
    *   **Validation**: Min: 0
*   `shippingFeePaise`:
    *   **Type**: Number
    *   **Required**: Yes
    *   **Validation**: Min: 0
*   `totalAmountPaise`:
    *   **Type**: Number
    *   **Required**: Yes
    *   **Validation**: Min: 0 (subtotalPaise + shippingFeePaise)
*   `shippingAddress`:
    *   **Type**: Object
    *   **Required**: Yes
    *   **Schema**: Matches the expanded User Address schema (firstName, lastName, phone, addressLine1, etc.)
*   `orderStatus`:
    *   **Type**: String
    *   **Enum**: `['pending_payment', 'processing', 'shipped', 'delivered', 'cancelled']`
    *   **Default**: `'pending_payment'`
    *   **Notes**: Admin can update this manually (except for moving *out* of `pending_payment` without a paid status).
*   `paymentStatus`:
    *   **Type**: String
    *   **Enum**: `['pending', 'paid', 'failed', 'refunded']`
    *   **Default**: `'pending'`
    *   **Notes**: Controlled strictly by Razorpay webhook/verification. Admin cannot arbitrarily change this to 'paid' without verification.
*   `razorpayOrderId`:
    *   **Type**: String
    *   **Required**: Yes (Generated when creating the order)
*   `razorpayPaymentId`:
    *   **Type**: String
    *   **Required**: No (Populated upon successful payment verification)
*   **Timestamps**: `createdAt`, `updatedAt`

---

## Important Rules

1.  **Stock Management**: Stock (`Product.variants.stock`) is **NOT** reduced when an `Order` is created (in `paymentStatus: 'pending'`). Stock is **ONLY** reduced via the backend when the payment is verified (`paymentStatus` transitions to `'paid'`). When this happens, the decrement must be implemented **atomically** (using MongoDB's `$inc` operator and a check for sufficient `stock >= quantity`) to prevent race conditions and overselling.
2.  **Order Immutability**: The `Order.items` array strictly copies the product details. It does not solely rely on a `ref` to the `Product` model for essential display fields to protect against future catalog changes.
3.  **Payment Verification**: The `paymentStatus` field is authoritative. It can only be updated to `'paid'` by the Razorpay payment verification logic.
4.  **Financial Values**: All financial amounts (`pricePaise`, `subtotalPaise`, `shippingFeePaise`, `totalAmountPaise`) are stored in the smallest currency unit (Paise for INR) as integers to avoid floating-point inaccuracies.
